# TV-4 Digital Control 2.0.0

Штатная прошивка установлена по Micro-USB на настольную ESP32-2432S028 с двумя разъёмами. Профиль платы — `panel-st7789`, дисплей ST7789, резистивный сенсор XPT2046. Испытания проводились на отдельной ESP32 при обесточенном приводе.

## Возможности

Семисекундная заставка с мотоциклом открывает приборную панель TV-4 DIGITAL. Она показывает RPM, скорость резания, диаметр, состояние датчика и время операции. Графики охватывают последние 30 секунд, 2 и 10 минут. Расчёты и моточасы различают DEMO и LIVE. Справочник содержит четыре фрагмента заводского рисунка, паспортные шаги резьбы и подачи. На экране доступны подбор оборотов по введённой скорости резания, расчёт проходов, геометрия резьбы и ориентировочное сверло под метчик. [Рычаги](tv4-controls.md) · [Резьбы](threading.md) · [Калькуляторы](calculators.md)

Датчик подключается через согласователь ко входу GPIO27. Потенциометр B5K относится к частотнику. Управление приводом остаётся аппаратным. Панель работает без интернета и карты microSD. [Подключение](wiring.md)

## Проверки программы

- PlatformIO успешно собрал пять профилей — два рабочих, два диагностических и штатный профиль ArduinoOTA. Все двенадцать активных GPIO имеют разные назначения.
- Все три набора CTest прошли под Clang/Emscripten и Node. В ядре выполнено 899 проверок, в том числе 2 000 000 интервалов датчика. Проверены миграция настроек, ограничение частоты записи, восстановление после ошибок и разделение статистики.
- Настоящий LVGL отработал 300 циклов сенсорной навигации в кадровом буфере 240 × 320. Свободная память LVGL до и после — 43 192 байта. [Главный экран](dashboard-v2.png) · [Интерактивный чертёж](controls-v2.png)
- Локальный Chrome отобразил телеметрию и убрал устаревшие показания после разрыва связи. [Как повторить проверки](testing.md)

## Проверки платы

USB-мост CH340 на COM3, ESP32-D0WD-V3 ревизии 3.1, Flash 4 194 304 байта. Защищённая точка доступа запустилась. Локальный HTTP API ответил кодом 200.

| Испытание | Фактический результат |
| --- | --- |
| Неполный Web OTA | Клиент передал 5 774 из ожидаемых 1 455 600 байт. Сервис отклонил файл, плата сохранила рабочий слот. |
| Полный Web OTA | Сервис принял 1 460 320 байт с проверкой SHA-256. Плата перезапустилась из `app0` в `app1`. |
| ArduinoOTA | Парольная аутентификация, проверка MD5 и запись прошли. Плата перезапустилась из `app1` в `app0`. На всех трёх загрузках стендовой сборки Serial показал `NVS=ok cal=1`. |
| Окончательная установка по USB | Загрузчик проверил хеш записи. Версия 2.0.0 стартовала из `app0`, подняла HTTP и перешла к тахометру в DEMO через семь секунд после появления заставки. Команды испытательного клиента исключены из этого образа. |
| Память и повторный запуск | Дождались штатного пятиминутного сохранения, перезагрузили плату и дождались главного экрана второй раз. При включённой точке доступа свободно 172 368 байт кучи ESP32, минимум в журнале — 171 648 байт. |

После второго запуска прочитаны все 20 480 байт NVS. Калибровка и обе копии настроек 1.0.4 побайтно совпали с резервной копией до обновления. Проверка CRC журнала 2.0 прошла. Сохранено 600 секунд суммарного питания, реальные счётчики шпинделя сохранили исходные значения во время DEMO. Команда `esptool verify_flash` отдельно сверила все 1 281 536 байт установленного приложения с файлом выпуска.

У ПК был только Ethernet. Клиент OTA на ESP32 передавал данные через собственный сетевой стек в физическую Flash. Телефон по радио, внешняя сеть STA и повторное подключение к роутеру требуют отдельной проверки. Подпись издателя и Secure Boot в этой сборке не настроены. [Порядок обновления](ota.md)

Хеши образов сверены с манифестом архива, четыре приложения побайтно совпали с выходом сборки. Разработка начата от `679fc23615ed` в ветке `development/v2.0`. [Архив](../release/TV4-Digital-v2.0.0.zip) · [Установка по USB](flash.md) · [Хранение данных](storage.md)

Коммит прошивки `36eff7dfe41bdca37d0d33f67a67e4d2061307ef` отправлен в закрытый GitHub. Отдельный запрос `git ls-remote` подтвердил этот хеш в ветке разработки. На рабочем ПК выпуск с отчётом доступен по тегу [v2.0.0](https://github.com/bangkok13/tv4-digital-control/tree/v2.0.0).

## Что проверить в мастерской

1. Проверить маркировку датчика и уровни согласователя. Подать на вход LIVE импульсы известной частоты, проверить «Н/Д» при потере сигнала, затем сверить показания с независимым тахометром.
2. На физическом экране проверить пальцем клавиатуру и попадание по номерам рычагов. Пользователь подтвердил тач в предыдущем выпуске. Для 2.0 касания проверены программным вводом LVGL.
3. Сверить таблички рычагов на конкретном ТВ-4. Проверить приём Wi-Fi в металлическом шкафу и длительную работу тахометра возле действующего частотника. [Открытые вопросы](open-questions.md)
