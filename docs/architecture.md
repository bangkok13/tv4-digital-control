# Устройство прошивки

| Компонент | Ответственность |
| --- | --- |
| `src/main.cpp`, `Application.*` | Инициализация и кооперативный цикл. Выбор источника данных, обработка действий пользователя, обновление единой `MachineState`. |
| `src/display`, `src/touch`, `src/discovery` | TFT_eSPI на HSPI, подсветка LEDC, XPT2046 на отдельной VSPI, считывание давления и медианы координат, проверяемая калибровка. |
| `src/ui/LvglPort.*`, `lib/PanelUI` | Синхронная выгрузка прямоугольника RGB565, касания и четыре экрана LVGL. Один добавочный экран подтверждает сброс. Тот же UI работает в стендовом тесте с кадровым буфером. |
| `src/sensors/PulseInput.*`, `lib/TV4Core/src/RPMService.*` | Метки времени из GPIO ISR и обработка интервалов в основном цикле. |
| `StatisticsService`, `SettingsService`, `Journal` | Подтверждённые интервалы, долговременные значения, сохранение и восстановление. |
| `DemoService` | Синтетическая кривая 0…1500 RPM длительностью 40 с. Первичные тестовые итоги 2 ч, 12 пусков. Данные существуют только в оперативной памяти. |
| `DiagnosticsService`, `ModbusService` | Причина сброса, память, Serial, состояние периферии. У интерфейса телеметрии привода есть только метод чтения. |

## Обороты и время

На каждом спаде ISR кладёт в очередь 64-битную метку `esp_timer_get_time()`. Очередь вмещает 127 необработанных фронтов. Критические секции защищают передачу данных между ISR и циклом ESP32. Одна итерация забирает до четырёх блоков по 32 отсчёта. При переполнении очередь и незавершённый интервал сбрасываются, число пропущенных отсчётов доступно через Serial. После разрыва снова требуются два фронта.

Расчёт использует `60 000 000 / (интервал_мкс × импульсов_на_оборот)`. Фронты, которые требовали бы скорости выше 6000 RPM, отбрасываются без сдвига опорной метки времени. Максимум шкалы меняет только рисунок. Вес нового отсчёта определяет экспоненциальное сглаживание цифр. Статистика использует исходные подтверждённые интервалы выше заданного порога, включая равенство. Среднее взвешено по времени, максимальное значение хранится в целых RPM. Время между последним фронтом и истечением тайм-аута в моточасы не попадает.

После первого фронта измеритель ждёт следующий до `65 с / PPR`; этого достаточно для захвата 1 RPM. После захвата тайм-аут равен большему из 350 мс и 2,5 последних периодов. При 1250 RPM и одной метке потеря сигнала определяется через 350 мс, при 10 RPM — через 15 с. На экране появляется «Н/Д» при следующем обновлении. Мгновенное обнаружение остановки на этих двух скоростях с одной меткой физически невозможно. Большой скачок периода может привести к повторному захвату. Сумма времени и число пусков накапливаются в 64 бит с насыщением. После перезагрузки новый подтверждённый сеанс наблюдения считается отдельным пуском. Переключение режима или PPR также начинает новый сеанс наблюдений.

## Память и питание

Буфер изображения занимает 7680 байт (240 × 16 строк × 2 байта). LVGL использует фиксированный пул 48 КиБ. На экране существует одно дерево виджетов; заголовок сохраняется при переходе, содержимое пересоздаётся только при навигации. Данные обновляются раз в 50…1000 мс, диспетчер LVGL обслуживается каждые 5 мс, период перерисовки 33 мс. Wi-Fi, Bluetooth и microSD в первом выпуске не инициализируются. Контроль памяти и причины последнего сброса использует штатные функции ESP32. Пользовательской блокирующей петли ожидания тача, датчика или RS-485 нет.

Настройки и реальные итоги имеют отдельные пары ключей Preferences/NVS. Запись содержит версию схемы, номер поколения, данные и CRC32. После записи в другой ключ данные читаются обратно. При включении выбирается наиболее свежая допустимая запись; при повреждении обеих копий применяются значения по умолчанию, ошибка отмечается в диагностике. Пустой раздел при первом включении соответствует DEMO. Отдельная калибровка привязана к профилю дисплея. [Модель хранения Espressif NVS](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32/api-reference/storage/nvs_flash.html)

Настройки записываются спустя 2 с после последней правки, повторные записи разделены минимум 10 с. Изменённая статистика сохраняется не чаще раза в 5 мин. При снятии питания может потеряться незаписанная часть этого интервала. Явно подтверждённый сброс LIVE сохраняется сразу; при ошибке оператор может повторить его. В DEMO подтверждение обнуляет только тестовые итоги. Диагностика показывает состояние NVS, а Serial сообщает об успешных и неудачных записях.
